# Project Lanes

This study uses separate lanes so that research evidence and project utility stay aligned but not conflated.

## `causetrace` Lane

Role:

- protocol definition
- trace capture
- morphology analysis
- cross-project synthesis
- hypothesis feedback

Evidence type:

- observational
- comparative
- morphology-focused

## `Project A` Lane

Role:

- first pilot application repo
- calibration-heavy and safety-sensitive tasks
- correction / review / fallback behavior

Best task shapes:

- signature calibration
- table-vs-title-block ambiguity
- rule conflict
- review and correction
- failing test repair

Evidence type:

- application-relevant
- prompt-template-relevant
- morphology-relevant

## `Project B` Lane

Role:

- second pilot application repo
- business logic and workflow tasks
- constraint-heavy feature and refactor work

Best task shapes:

- feature addition
- business logic fix
- workflow adjustment
- refactor
- review

Evidence type:

- application-relevant
- prompt-template-relevant
- morphology-relevant

## Lane Boundary

- Project conclusions stay per-project first.
- Cross-project synthesis compares trends only.
- Native corpus conclusions in `causetrace` stay separate from application repo sessions unless explicitly re-reviewed.
