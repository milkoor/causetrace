# Cross-project Prompt Morphology Apply-First Phase

## Status

Active default phase after v0.1 / v0.2 completion.

## Purpose

Apply the current prompt morphology findings to real work in `Project A` and `Project B` before starting any broader v0.3 pilot.

This phase is about adoption, not new controlled expansion.

## Operating Rule

- Use the current project-level prompt templates in real tasks.
- Prefer natural traces generated by ongoing development work.
- Do not launch a new controlled pilot immediately.
- Keep `causetrace` in observation mode: record traces, compare morphology, and preserve project-level separation.

## Project Usage

### `Project A`

Apply the existing prompt guidance to:

- false positive table checks
- `need_review` safety gating
- OCR fallback / unavailable cases
- `grid_template` and calibrator safety work
- GUI regression and calibration tasks

### `Project B`

Apply the existing prompt guidance to:

- record extraction and reporting
- order / workflow extraction
- SMS and template boundary cases
- permission / role-gated paths
- cleanup and refactor tasks

## Evidence Goal

The goal is to accumulate natural traces that show whether the existing templates:

- reduce invalid retry
- reduce unnecessary intervention
- improve completion quality
- preserve or improve runtime morphology

## v0.3 Gate

Only start `v0.3` if it directly supports:

- Phase 3D Tier 2 acquisition needs, or
- a project-specific rollout decision

## Boundary

This phase must not be promoted into:

- a universal prompt policy
- a `causetrace` core schema change
- a merged cross-project truth
