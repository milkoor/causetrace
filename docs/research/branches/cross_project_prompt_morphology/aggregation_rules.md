# Aggregation Rules

The study compares projects, but it does not merge them into one undifferentiated truth.

## Core Rule

Each project must be analyzed independently first.

Cross-project reports may compare trends, but they must not merge project-level outcomes into a single global conclusion unless task type, runtime, prompt variant, and project context are explicitly controlled.

## Allowed Aggregation

- compare the same prompt variant across projects
- compare the same task family across projects
- compare the same runtime across projects
- summarize trend direction across projects

## Disallowed Aggregation

- averaging project results into one conclusion without context control
- treating `Project A` and `Project B` as interchangeable
- treating controlled-study sessions as native truth
- promoting a cross-project trend into a causal claim without per-project evidence

## Required Context for Any Cross-Project Claim

Every cross-project claim must report:

- project count
- task types
- runtime(s)
- prompt variants
- outcome distribution
- morphology distribution

## Divergence Rule

If project-level trends diverge, preserve the divergence instead of averaging it away.

Divergence is a result, not a failure.
