# Cross-project Prompt Morphology Pilot v0.3 Options

## Status

Optional next direction only.

## Purpose

v0.3 should only be started if it directly supports follow-on project work or Phase 3D Tier 2 needs.

## Option A. Apply templates first

Use the current project-level prompt templates in day-to-day work.

Plan:

- apply the v0.1 / v0.2 prompt findings in real project work
- collect natural traces as work continues
- avoid launching a new controlled pilot immediately

Best when:

- the goal is to turn pilot findings into immediate workflow value
- the team wants lower-friction adoption before another measurement round

## Option B. Failure / near-failure focused pass

Target the morphology that the current pilot did not fully cover.

Plan:

- prioritize failure
- prioritize near-failure
- prioritize human intervention
- prioritize correction triggers
- reuse the same prompt families where possible

Best when:

- the next objective is to support Phase 3D Tier 2 acquisition needs
- the study needs denser negative examples and correction traces

## Option C. Multi-runtime comparison

Hold the task constant and vary runtime.

Plan:

- same task
- same prompt variants
- different runtime
- compare trace morphology across runtimes

Tradeoff:

- higher cost
- more cross-runtime noise
- not recommended as the immediate next step unless a runtime comparison is specifically required

## Recommended default next step

Pause broad prompt morphology expansion.

Apply the v0.1 / v0.2 findings to active project workflows first.

Start a v0.3 only if it directly supports Phase 3D Tier 2 acquisition or a project-specific rollout decision.

## Boundary

v0.3 remains a controlled study option.
It must not be promoted into a universal prompt policy or into a `causetrace` core schema change.
